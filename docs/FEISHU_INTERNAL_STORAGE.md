# Cofound 内部飞书资料存储契约

当前 V1 已在企业共享文件夹中建立独立 Drive 根目录与 Base 薄索引。正式索引表名称为 `项目文件索引_v1_20260824`；资源 token 与用户登录态只保存在本机被忽略的配置中，不写入本文档或交付包。个人云盘中的旧目录只作为历史资料保留，不再承接新的正式同步。

## 1. 定位

Cofound 本地工作台继续是项目、事实字段、证据、分析结果与管理状态的唯一主系统。飞书只承担公司内部的原文件存储与分发：

- Drive 保存 BP 原件和补充材料的每一个版本；
- Base 保存一行一个文件的薄索引，便于检索和回到 Drive；
- Base 不复制投资事实、管理判断或 Codex 分析，不成为第二套项目数据库；
- 外部分享继续走独立的 Vercel 选择性分享链路，不从该内部目录直接公开。

## 2. 固定目录

企业共享父目录中先建立 Cofound 协作根目录。正式配置必须把 `01_项目原件与补充材料` 的 `folder_token` 交给本地程序，并将 `storageScope` 明确设为 `enterprise_shared`。未标记、标记为个人目录或无法核验的配置会停止正式同步。适配器在资料根目录下按需、按精确名称创建：

```text
Cofound Investment Office｜企业内部协作/
└─ 01_项目原件与补充材料/
   ├─ 00_团队收件箱（待导入）/
   └─ <项目名称> [<project_id>]/
      ├─ 01_BP 原件/
      └─ 02_补充材料/
```

远端文件名包含本地 BP 版本号和 SHA-256 前 12 位，例如：

```text
BP-v001-7f0d23c54c8a-项目A BP.pdf
BP-v002-9e51e7dca4d1-项目A BP 更新版.pdf
contracts_orders-10ea783c45f2-订单证明.pdf
```

V1 不设置“只保留最近 5 版”等保留策略。适配器不覆盖、不移动、不删除任何远端文件；每个 BP 版本和补充材料均永久保留，后续另行确认归档制度。

### 团队收件箱

`00_团队收件箱（待导入）` 是飞书到本机的追加式入口。团队成员只需把新 BP 或更新版放进该目录；本机工作台会先列出自然语言计划，再由用户确认拉取。首版固定串行处理：

- 未见过的新文件：下载并导入为新项目或新版本；
- 已在本机存在的相同内容：跳过，不生成重复版本；
- 相同内容对应的项目已在本地回收站：校验内容后恢复原项目，不生成 v2；
- 同一公司的不同内容：恢复或沿用原项目并追加为 v2、v3；
- 不支持的类型、超限文件或无法安全判断的内容：停止或标记失败，不猜测归属。

程序只读列取并下载收件箱对象，不移动、不重命名、不覆盖、不删除飞书远端文件。收件箱处理回执保存在本地，用于判断远端文件是否变化；再次扫描未变化内容会直接跳过。

## 3. Base 薄索引

正式使用企业共享目录中的 `Cofound 企业内部数据中枢` Base 与官方表 `项目文件索引_v1_20260824`。同一 Base 中另设独立的 `产品改进台账`，不与文件索引混写。表内字段名称必须与下表完全一致；字段写入前适配器会先读取 schema，缺字段就停止，不会猜字段或静默降级。

| 字段             | 推荐类型       | 说明                           |
| ---------------- | -------------- | ------------------------------ |
| 同步键           | 文本（主字段） | 等于完整 SHA-256，全局幂等键   |
| 项目 ID          | 文本           | Cofound 本地项目 ID            |
| 项目名称         | 文本           | 展示用途                       |
| 本地文件 ID      | 文本           | Cofound 本地文件或材料 ID      |
| 资料类型         | 文本           | BP 或材料分类                  |
| BP 版本          | 数字           | 非 BP 可为空                   |
| 原始文件名       | 文本           | 用户导入时文件名               |
| 云盘文件名       | 文本           | 飞书 Drive 中的归档文件名      |
| SHA-256          | 文本           | 内容哈希；同步前后校验         |
| 文件大小（字节） | 数字           | 本地确定性元数据               |
| MIME 类型        | 文本           | 文件 MIME 类型                 |
| 飞书文件链接     | 文本（URL）    | Drive 浏览链接                 |
| 飞书文件 Token   | 文本           | Drive 文件定位符，不是访问凭据 |
| 同步状态         | 文本           | 当前固定为“已同步”             |
| 同步时间         | 日期时间       | 写入时间                       |
| 同步操作者       | 文本           | 发起同步的可识别用户昵称       |

Base 不使用附件字段保存唯一副本；唯一原件在 Drive 中。

## 4. 本地配置

配置只允许保存资源定位符：

```json
{
  "driveRootFolderToken": "fld_xxx",
  "baseToken": "bas_xxx",
  "baseTableId": "tbl_xxx",
  "feedbackBaseToken": "bas_xxx",
  "feedbackTableId": "tbl_feedback_xxx",
  "storageScope": "enterprise_shared"
}
```

`storageScope` 不是凭目录名猜测得出的展示文案。只有在确认目录位于企业共享文件夹、团队成员继承正确权限且链接分享关闭后，才写入 `enterprise_shared`。本地程序会据此在界面标明“企业共享”，并拒绝把正式同步计划发往 `personal` 或 `unknown` 目标。

### 2026-08-24 权限验收快照

- 共享根、三个子目录和 Base 均可由当前 5 名企业内部成员访问，未发现外部直接协作者；
- 三个文件夹的链接分享为关闭状态，未发现互联网公开链接；
- Base 当前允许企业成员持链接读取；
- 当前策略允许未来再添加外部协作者，但这不代表当前已有外部访问；
- 当前 5 名内部成员均为完整权限。若需要改成最小权限、关闭未来外部协作者能力或收紧 Base 链接范围，必须作为单独的权限变更逐项确认，程序不会静默修改。

以上是验收时点的有效权限结果，不替代飞书企业级 DLP、审计日志或后续权限复核。

不得写入、提交或分发 `appSecret`、`accessToken`、refresh token、验证码或个人登录态。飞书身份由每台电脑已经授权的 `lark-cli` 安全配置负责。所有 Drive/Base 调用都显式使用 `--as user`。

## 5. 同步 Loop

每个项目同步按以下固定循环执行：

1. 本地重新计算文件 SHA-256 和大小；与数据库元数据不同则停止。
2. 执行 `lark-cli auth status --json --verify`，确认当前登录态可用。
3. 读取 Base 字段 schema；字段不完整则停止。
4. 按 SHA-256 查询 Base：已存在则回读核对并跳过。
5. 精确列取 Drive 子目录；缺少项目目录或资料目录时用 `drive +create-folder --as user` 创建，再列取回读。
6. 精确检查带哈希的远端文件名；不存在时用 `drive +upload --as user` 新建上传。绝不传 `--file-token`，因此不会覆盖。
7. 列取目标目录，回读并确认文件 token、文件名与链接。
8. 用 `base +record-upsert --as user` 创建薄索引记录。
9. 用返回的 `record_id` 执行 `base +record-get`，核对 SHA-256、项目 ID 和 Drive file token。
10. 生成结构化 operation receipt，记录创建数量、跳过数量、回读检查与失败原因；归档统计绑定当前 Drive/Base 目标，切换目录后不会把个人旧目录的历史数量算进企业共享目录。

如果文件已经上传但 Base 写入失败，下次运行会通过带哈希的远端文件名找回该文件，只补索引，不重复上传。若 Base 中同一 SHA-256 出现多行、Drive 同目录出现同名对象或回读值不一致，适配器会 fail closed，等待人工处理。

## 6. Dry-run 与测试边界

`planFeishuProjectSync` 只验证本地文件并生成不可变计划；`syncProjectToFeishu(plan, { dryRun: true })` 不调用 CLI、不写飞书。生产执行可以注入真实 `SpawnLarkCliRunner`，单元测试注入 fake runner，以验证：

- 所有 Drive/Base 业务命令均携带 `--as user`；
- 同一 SHA-256 重跑不再上传或建索引；
- 上传使用相对文件名与受控 cwd；
- 命令中不存在删除或 `--file-token` 覆盖参数；
- 每次写入均有读回验证；
- 失败仍返回可审计回执。

适配器不会自动追加 `--yes` 绕过飞书 CLI 的高风险确认门禁。如果未来新增权限调整、删除、覆盖、移动等高风险动作，必须按飞书 CLI 协议逐次展示目标并取得明确确认。

## 7. 本地回收站与版本边界

“删除 BP”在 V1 中定义为把整个项目移入本地回收站：项目从默认清单隐藏，但项目 ID、原文件、字段、分析历史、管理判断和版本关系完整保留。此操作不删除飞书文件，也不自动撤销已经存在的外部分享。恢复后继续使用原项目 ID。

如果飞书收件箱再次出现该项目的相同 BP，系统会在内容校验后恢复原项目；如果出现同公司的新内容，则先恢复再追加为下一 BP 版本。批量编辑仅修改结构化字段、标签和管理状态，不会改写 BP 文件字节。任何源文件内容更新都必须以新文件、新版本进入版本链。
